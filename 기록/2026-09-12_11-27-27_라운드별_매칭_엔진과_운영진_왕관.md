# 라운드별 매칭 엔진과 운영진 왕관

- 작업 시각: 2026-09-12 11:27 ~ 11:50 KST
- 작업 도구: Claude Code (계획·최종 점검 본체 Opus 4.8, 구현 Sonnet 서브에이전트 2개(순차), 검증 Opus 서브에이전트 2개)
- 관련 요청: 033

## 1. 요청 번호와 요청 요약

- 요청 033: 대진 시스템을 라운드별로 다른 시드 매칭 방식으로 짤 수 있게. 라운드 수를 정할 때 각 라운드에 동일시드매칭(점수 최인접)/인접시드매칭/랜덤시드매칭을 골라 체크하면 그 방식대로 시드표 점수를 반영해 대진이 만들어지게.
- 사용자 답변: 인접 = 실력 균형 매칭(강약 섞기). 쉬는 사람은 역할 기준(게스트→늦참→운영진→회원). 운영진 6명(로토·백구·구구·이코·뉴키·단우)은 시드표·대진에 왕관(👑) 표시. 늦참 표시 기능도 필요.

## 2. 계획 (본체)

- 서버 검증(`validate`)이 schedule payload를 화이트리스트로 정리하므로, 매칭 방식·늦참 정보는 저장하지 않고 **생성 시점(클라이언트)** 에서만 사용. 저장 형식은 기존과 동일(400 위험 회피).
- 회원 점수를 `/api/people`에 추가해 클라이언트가 점수 기반 매칭을 하게 함(게스트는 요청 030에서 이미 추가됨).
- 2단계로 분리: 1단계 왕관 표시, 2단계 매칭 엔진+UI.

## 3. 수행 내용과 변경 파일

### 1단계 왕관 (커밋 4ed00ad)
- `dist/server/boards-client.js`: client 안에 `OPERATORS`(6명 이름) 집합과 `crown(name)` 헬퍼 추가. 시드표 회원 이름 셀, 대진 경기 카드(보기 모드), 대진 만들기 참가자 목록에 왕관 적용. 편집용 `<select>`에는 미적용.
- `dist/server/boards-style.js`: `.crown` 스타일.

### 2단계 매칭 엔진 (이번 커밋)
- `dist/server/boards.js`: `/api/people`에서 회원 `points`도 조회·병합.
- `dist/server/boards-client.js`:
  - `generate(roster,courts,rounds,methods)`로 교체. roster={id,name,type,points,late,operator}. 라운드마다 셔플 후 역할(회원0<운영진1<늦참2<게스트3)·누적 출전수로 정렬해 앞에서부터 cap*4명 출전, 나머지 휴식(등급 내 공평 순환). 방식: same=점수순 연속 4명, balanced(인접)=사분위 라운드로빈(강약 혼합), random=무작위. 팀 분할은 same/balanced에서 (최고+최저) vs (중간 둘)로 균형, random은 무작위.
  - `openPicker`: 라운드별 방식 선택 UI(`#roundMethods`, 동일/인접/랜덤 버튼), 늦참 토글 버튼(참가자별), 안내문 교체, 생성 시 roster 구성 후 generate 호출.
  - CSS: `.round-methods/.rm-*/.late-btn`.
  - `check-login.mjs`: 회원 points 검사 추가.
