# 즉석 게스트 추가와 대진표 삭제 버튼

- 작업 시각: 2026-09-12 12:00 ~ 12:20 KST
- 작업 도구: Claude Code (Opus 4.8 본체 계획·최종점검, Sonnet 서브에이전트 구현 1개, Opus 서브에이전트 검증 1개)
- 관련 요청: 035, 036

## 1. 요청 번호와 요청 요약

- 요청 035: 새로 급히 오는 게스트를 대진 만들 때 '추가하기' 버튼으로 즉석에서 넣고 대진에 포함(체크)되게.
- 요청 036: 운영진이 대진표 상세로 들어갔을 때 삭제할 수 있는 버튼도 있게.

## 2. 계획 (Fable/본체)

- 서버 검증을 먼저 확인: `validate()`는 `names` 중복 금지, `participantIds`는 실제 회원 검증 없이 저장, 정산(`settleSchedule`)은 회원이 아닌 이름을 안전하게 무시. → 즉석 게스트는 임시 uuid id로 넣어도 안전하며 랭킹·시드에 영향 없음.
- 035: `openPicker`에 즉석 게스트 입력+버튼 추가. 임시 게스트는 `people`에 `{type:'guest',points:0,adhoc:true}`로 추가·자동선택. 기존 대진 재편집 시 `participantIds`/`names`로 즉석 게스트 복원(같은 id로 다시 넣어 체크 유지). 이름 중복은 클라이언트에서 사전 차단(서버 중복 거절 방지).
- 036: 서버 라우팅에 운영진 전용 `DELETE /api/posts/:id` 추가(정산 완료 대진표는 409로 차단). 상세 화면에 확인창 딸린 삭제 버튼(공지에도 동일).

## 3. 수행 내용과 변경 파일 (Sonnet 1개)

- `dist/server/boards-client.js`
  - `openPicker`: 재편집 시 즉석 게스트 복원 1줄, 검색창 아래 `.add-guest`(입력 `#newGuestName` + 버튼 `#addGuest`), `addGuest` 핸들러(빈값·중복 이름 거절 → 새 게스트 추가·선택·게스트 탭 전환·검색 초기화·포커스), Enter 키로 추가.
  - `detail`: 운영진 버튼을 `.detail-actions`로 묶고 `#deletePost`(class `danger`) 추가. 삭제 핸들러(확인 → `DELETE` + `x-kokkiri-editor` 헤더 → 목록으로 이동, 실패 시 메시지).
- `dist/server/boards.js`: `/api/posts/:id`의 GET 처리 뒤·PUT 405 가드 앞에 `DELETE` 분기(운영진 403 게이트, 없음 404, 정산 완료 대진표 409, 삭제 후 `{deleted:true}`).
- `dist/server/boards-style.js`: `.add-guest`, `.detail-actions`, `.danger`/`.danger:hover` 규칙 추가.
- `check-login.mjs`: 클라이언트에 `addGuest`/`adhoc`/`deletePost` 존재 단언 + DELETE 엔드포인트 수명주기 테스트(비운영진 403, 삭제 200, 삭제 후 404, 정산 완료본 409).

## 4. 검증 결과 (Opus 검토 + 테스트)

- `node check-login.mjs`(번들 node) PASS.
- Opus 검증 7개 항목 모두 PASS, 종합 판정 SHIP:
  1. 클라이언트 인라인 안전(외부 스코프 참조 없음, ReferenceError 위험 없음).
  2. 즉석 추가 정확성(빈값·중복 거절, 추가 후 선택·체크·생성 포함, points 0은 최저 시드·먼저 쉼으로 의도대로).
  3. 랭킹 안전(정산이 비회원 id 무시, `add()` 가드로 크래시·오염 없음).
  4. 재편집 복원(names·participantIds 인덱스 정렬 성립, 같은 id로 체크 유지, 이름 접미사 이중부여 없음, 레거시 대진표는 이름 매칭으로 우아하게 대체).
  5. DELETE 엔드포인트 배치·게이트·404·409 정상, 기존 GET/PUT/settle 라우트 영향 없음.
  6. 삭제 버튼 게이팅(운영진 전용, 정산 완료 대진표 제외, 확인창, 헤더, 이동) 의도 부합.
  7. 회귀: 테스트 PASS, `dist`에 `__name` 없음, `wrangler.jsonc` `keep_names:false` 불변.
- Opus가 발견한 사소한 요건 누락(035 "시드표 미반영"): 즉석 게스트가 세션 동안 시드현황 게스트 탭에 잠깐 표시됨(새로고침 시 사라짐, 저장·랭킹 영향 없음). → 본체가 `seeds()` 게스트 탭 필터에 `&&!p.adhoc` 한 줄 추가로 해결. 테스트 재실행 PASS.

## 5. 최종 점검 (Fable/본체)

- 즉석 게스트: 임시(이 대진 한정), 랭킹·시드표·서버 데이터 미반영, 재편집 시 유지. 이름 중복만 사전 차단.
- 삭제: 운영진 전용, 정산 완료 대진표는 보호(삭제 불가), 확인창으로 오삭제 방지.
- 알려진 특성: 정산(점수 확정)된 대진표는 이미 랭킹에 반영되어 되돌릴 수 없으므로 삭제도 막았다. 필요 시 정산 취소·역산 기능은 별도 요청으로.

## 6. 미완료 사항과 다음 단계

- 이어지는 요청 037(승패 슬라이더 UI·회원 기록)·038(대진 종료·MVP·자동 정산)·039(랜덤 게임 승 버튼 제거·점수 미반영)는 승패/정산/스케줄 데이터 모델을 함께 바꾸므로 별도 웨이브로 진행한다. 특히 039를 위해 라운드별 매칭 방식(최소 random 여부)을 대진표 payload에 저장하도록 서버 `validate()`를 확장해야 한다(현재는 생성 시에만 쓰고 저장 안 함).
