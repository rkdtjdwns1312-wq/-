# 주간 출석·승·패 초기화(새 대진마다)와 순위 변동 화살표 색

- 작업 시각: 2026-09-12 13:50 ~ 14:05 KST
- 작업 도구: Claude Code (Fable 본체 직접 처리 — 서버·표시 수정, 테스트·로컬 DOM 확인)
- 관련 요청: 047

## 1. 요청 번호와 요청 요약

- 요청 047: 시드현황의 출석/승/패는 매 주기(대진)마다 0으로 새로 기록. 다만 시드 점수·순위는 계속 누적. 순위 변동은 상승 빨강↑(숫자), 하향 파랑↓(숫자). (사용자 선택: 초기화 시점 = "새 대진 만들 때마다".)

## 2. 계획 (Fable/본체)

- 초기화 시점은 사용자 선택대로 "새 대진 생성 시". 서버에서 대진(schedule)이 version 0으로 처음 INSERT될 때 ranking_members의 attendance·wins·losses만 0으로 UPDATE. points·seed·rank·previous_rank는 건드리지 않아 누적 유지.
- 순위 변동 화살표는 이미 있으나 색이 초록/갈색이라, 상승=빨강·하향=파랑으로 교체.

## 3. 수행 내용과 변경 파일 (Fable 직접 처리)

- `dist/server/boards.js`: PUT의 version 0 & kind schedule & 실제 삽입(result.meta.changes) 시 `ensureRankingMembers` 후 `UPDATE ranking_members SET attendance=0,wins=0,losses=0`. 점수/시드/순위 불변.
- `dist/server/boards-client.js`: 런타임 주입 스타일(extraStyle)의 `.rank-movement`(초록 #03a84e)→빨강 #e5484d, `.rank-down`(#9c3025)→파랑 #2f6fed. (이 규칙이 boards-style.js보다 나중에 적용돼 실제 화면을 지배하므로 여기서 고침.)
- `check-login.mjs`: 새 대진 생성 후 시오의 attendance/wins/losses=0, points=101(누적 유지) 검증 추가.

## 4. 검증 결과 (본체 검토 + 테스트 + DOM)

- `node check-login.mjs` PASS(초기화 검증 포함).
- 로컬 DOM: `.rank-movement` 계산색 rgb(229,72,77)=빨강, `.rank-down` rgb(47,111,237)=파랑. 회원표 출석/승/패 0으로 표시(정산 전), 점수/순위 유지.
- 순위 화살표 규칙이 두 곳(boards-style.js 추가분 + extraStyle)에 생겼던 문제 → boards-style.js 중복 제거하고 extraStyle만 유지.

## 5. 최종 점검 (Fable/본체)

- 흐름: 정산(대진 종료) 시 점수·순위·출석/승/패 반영 → 다음 대진 생성 순간 출석/승/패 0 → 새 대진 결과가 다시 기록. 점수·시드·순위는 계속 누적, 화살표는 직전 정산 대비 변동(빨강↑/파랑↓).
- 주의: 새 대진을 만들면(정산 전이라도) 이전 대진의 출석/승/패 표시는 0으로 초기화된다. 실수로 만든 대진은 삭제해도 초기화는 되돌아오지 않으니, 과거 주간 숫자가 필요하면 정산 기록(ranking_events)으로 확인. 콕끼리는 아직 실제 정산 이력이 없어 영향 없음.
- 콕끼리는 수(소정모)·토(정모) 2회이며, "새 대진마다 초기화"이므로 각 정모가 별개 기록이 된다(사용자 선택).
