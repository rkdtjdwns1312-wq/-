# 요청 133 — 숨김 명단 중복 이름 수정

## 요청

- 현재 표시된 회원 박상.을 박상, 게스트 지성.을 지성으로 바꾸려는데 이미 있는 이름 오류 발생. 원인 조사·수정 및 실제 이름 변경 요청.
- 코드 people/update 중복조회에 hidden=0 조건이 없어 숨김 명단도 충돌 처리함을 확인. 실제 운영 데이터 확인 및 DB 제약/정산 이력 안전성을 검토 중.
- 숨김 사람 삭제/병합하지 않는다. 사용자 지정 대상의 이름만 변경하고 ID·점수·순위·승패·출석·감사 이력은 유지한다. 별개의 활성 인물 충돌이 있으면 임의 병합하지 않는다.
- Astra에 서버와 회귀 검사 위임, 본체 운영 상태 확인/통합/배포.

## 구현·검증

- 생성/수정/이관의 중복 검사는 활동 명단(hidden=0)만 대상으로 변경한다. 활성 회원·게스트 간 중복 및 동시 저장 충돌은 계속 차단한다.
- 기존 회원 테이블의 전역 UNIQUE 제약도 원인이므로 `0020_active_people_names.sql`로 활성 이름에만 부분 UNIQUE 인덱스를 적용한다. 기존 행/ID/rowid/정산 이벤트/점수 이력과 트리거를 보존하는 원자적 테이블 재구성이다. 이미 활성 동명이인이 있으면 임의 병합하지 않고 마이그레이션 전체를 취소한다.
- 과거 대진은 참가자 ID를 우선하며, ID 없는 옛 대진에서 재사용 이름·이름 변경 이력으로 신원이 모호하면 마감/긴급교체를 거절해 다른 사람에게 점수가 연결되지 않도록 보호한다. 과거 게시글 자체는 다시 쓰지 않는다.
- `check-hidden-name.mjs` PASS: 숨김/활성 이름 재사용, 두 이름 변경과 점수/순위/승패 유지, FK 켜진 채 이력 있는 DB 마이그레이션/재실행/실패 롤백, 이관, 활성 중복 거절, 동시성, 감사 쓰기 실패 롤백, ID 기반 정산/취소 및 옛 대진 보호.
- 기존 check-server-audit의 ‘숨김 이름이면 거절’ 기대는 새 정책과 충돌해 발견되었고, 숨김 기록을 보존하며 변경 허용하는 검사로 대체한다.
- 운영 화면 사전 확인: 박상. 회원 9위/B+/99점/순위▲2/점수▲5/출석1·승4·패0, 지성. 게스트 7위/A/101점/점수▼1/출석1·승1·패3. 활성 이름에서 박상·지성의 별도 동명이인 없음. 배포 이후 이름만 실제 변경할 예정.

## 핵심 명령

숨김 명단 때문에 발생하는 잘못된 이름 중복 오류를 고치고 박상.·지성.의 끝 마침표를 제거한다.
