- 관련 요청: 065(삭제 버그), 066(점수 변동 표시)

## 1. 요청 요약

- 065: 대진표 삭제 버튼을 눌러도 제목이 게시판(목록)에 남는 버그를 고쳐달라.
- 066: 마감으로 반영되는 점수 변동도 순위처럼 화살표(위/아래)+수치로 표시. 규칙은 순위와 같고, 다음 대진 시작 시 표시가 사라진다.

## 2. 원인 분석 (Fable/본체)

- 삭제 버그: 라이브 목록에 제목이 빈 `legacy-schedule`(옛 단일 대진표)가 남아 있었다. `boards.js`의 `preserveLegacy`가 목록·상세 GET마다 옛 `schedules`(id=1)에서 `INSERT OR IGNORE`로 board_posts에 되살렸다. 그래서 운영진이 삭제해도 다음 조회에서 다시 생겼다. (마이그레이션 0004가 이미 legacy-schedule를 넣었으므로 preserveLegacy는 중복이자 버그의 원인.)
- 점수 변동: 순위 변동은 `previous_rank`(정산 직전 순위)로 화살표를 그린다. 점수는 정산 직전 점수를 저장할 컬럼이 없어 새로 추가해야 한다.

## 3. 수행 내용과 변경 파일 (본체 직접 구현)

### 065 삭제 버그
- `dist/server/boards.js`: `preserveLegacy` 함수와 두 호출부(목록 GET·상세 GET) 제거.
- `drizzle/0008_points_movement_and_legacy_cleanup.sql`: `DELETE FROM board_posts WHERE id='legacy-schedule';` (남은 옛 대진표 정리).

### 066 점수 변동 표시
- `drizzle/0008...sql`: `ALTER TABLE ranking_members ADD COLUMN previous_points INTEGER NOT NULL DEFAULT 0;` + 최근 정산(유효한 정산)의 `points_before`를 복원(`COALESCE(...서브쿼리..., points)`) → 방금 마감한 정모의 점수 변동이 바로 보이고, 정산 이력 없는 회원은 변동 표시 없음.
- `dist/server/boards.js`:
  - 정산(settleSchedule): UPDATE에 `previous_points=?`(정산 직전 점수=`byId.get(id).points`) 추가.
  - 마감 취소(unsettleSchedule): `previous_points=next.points`(화살표 해제, previous_rank와 동일 방식).
  - 새 대진 생성(version 0 초기화): `SET attendance=0,wins=0,losses=0,previous_rank=rank,previous_points=points` → 순위·점수 화살표 모두 사라짐(사용자 규칙: 다음 대진 시작 시 초기화).
  - `/api/rankings` SELECT에 `previous_points` 포함. POST `/api/people`(회원 추가) INSERT에 `previous_points=points`.
- `dist/server/rankings.js`: `ensureRankingMembers` INSERT에 `previous_points`(=시작 점수) 추가(새 회원 화살표 없음).
- `dist/server/boards-client.js`: `pointsMove(row)` 추가(점수>이전=▲빨강, <이전=▼파랑, 같으면 없음), 시드현황 점수 열에 `점수 + 변동` 렌더.
- `dist/server/boards-style.js`: `.pts-delta`(간격·크기). 색은 순위와 동일한 `.rank-movement`(빨강)·`.rank-down`(파랑) 재사용.
