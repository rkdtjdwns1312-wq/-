## 4. 검증 결과

- 테스트: `kokkiri-site`에서 번들 Node v24.19.0으로 `node check-login.mjs` 실행 → `PASS: correct/incorrect passwords, 5-attempt limit, expiry, origin checks, missing configuration, public secret isolation, existing operator route and unauthenticated write rejection.` (Fable 실행, 미리보기 서버 기동 시에도 동일하게 PASS)
- git: `kokkiri-site` main = b13f3a6, origin/main = 4492a7a, `## main...origin/main [ahead 5]`, 작업 트리 clean.
- Opus 검증(서브에이전트 1개, 조건부 통과): git log·상태·해시, 테스트 PASS, 엑셀 SHA-256(최신본=문서 폴더본, 이전본 별도), 비밀값 Grep 0건, 문서에 적힌 경로 21개 존재, 기록 6개의 관련 파일 목록이 각 커밋 `--stat`과 일치, 메인.md 표 24행 4열·링크 7개 일치를 확인했다. 발견 사항과 조치:
  - (A) 실질 문제: `rankings.js`는 이름·점수·순위만 초기값으로 담고 시드는 `seedForPoints()`로 재계산한다. 엑셀 시드 열이 A+인 **주밤(115점)·로토(104점)** 는 계산값이 A(A+는 120점 이상)여서 배포 후 화면 시드가 바뀐다. 코드는 사용자 요청(점수로 자동 계산)대로이므로 변경하지 않고, `메인.md` '현재 상태'에 사용자 확인 항목으로 올렸다. → 사용자가 01:50 "A가 맞다"고 확인하여 요청 023으로 명단 파일을 A로 맞추고 커밋했다(280aa75). 기록·요청이력의 "시드를 그대로 사용" 표현은 "점수·순위는 그대로, 시드는 자동 계산"으로 고쳤다.
  - (B) 엑셀 2번 시트 '26-08-19 변경'은 빈 시트다. 기록의 "참고용" 표현을 "빈 시트, 미사용"으로 고쳤다.
  - (C)(D) 이 기록과 메인.md의 7번째 기록 반영·검증 절 갱신을 Fable이 마무리했다.
  - (E) 운영진 로그인 제한은 오입력만이 아니라 15분 내 모든 시도를 세므로(정답 포함) 기록 표현을 "5회 시도 제한"으로 고쳤다.
  - CLAUDE.md의 Codex 사후 정리 기록 예외 조항 날짜 문구를 손질했다.
  - 최신본·이전본 xlsx는 셀 데이터가 동일하고 파일 메타데이터만 다르다(기준값 변화 없음).

## 6. 미완료 사항과 다음 단계

- **공개 홈페이지 배포 미완**: 로컬 5커밋(운영진권한 버튼, 공지 날짜 숨김, 홈 카드 정렬, 하단 N일 문구, 점수·시드 시스템)이 공개 주소에 반영되지 않았다. 사용자가 Codex 대화(스레드 "배드민턴 점수와 순위의 변동을 자동적으로 확인할 수 있는 프로그램을 만들고 싶어")에 **"계속 진행해줘"** 를 보내면 Codex가 원본 업로드 → 새 버전 배포 → 공개 주소 확인을 이어간다. Codex 보고에 따르면 비밀 환경변수 `OPERATOR_PASSWORD`는 이미 설정되어 있다.
- 배포 후 사용자 확인 순서는 `메인.md` '현재 상태와 미완료 사항' 참고.
- Enter 키 제출 동작은 실제 브라우저에서 확인 필요(위 5절).
- 루트 legacy 저장소(`배드민턴 프로그램 만들기\.git`)는 다른 계정 소유로 git 조회 불가. 현재 홈페이지와 무관하므로 방치.

## 7. Git 동기화·배포 결과
