# 문서를 저장소 안으로 이동해 코덱스 협업 보장

- 작업 시각: 2026-09-12 02:23 ~ 02:35 KST
- 작업 도구: Claude Code (Fable 직접 처리 — 문서·규칙 이동과 설정 파일 1개)
- 관련 요청: 027

## 1. 요청 번호와 요청 요약

- 요청 027: "모든 작업을 내가 코덱스로 해도 작업하여 협업할 수 있도록, 작업에 문제가 없도록 고려해 주어야 해. 추후를 위해서라도."

## 2. 계획 (Fable)

- 문제: Codex는 샌드박스(별도 Windows 사용자)에서 실행되며 쓰기 권한이 작업 폴더 `배드민턴 프로그램 만들기` 안으로 제한된다. 그동안 문서를 둔 `콕끼리 홈페이지 관리` 폴더는 그 밖이라 Codex가 쓰려면 매번 승인이 필요했고, 사용량 제한·자동 실행 상황에서는 거절됐다(요청 017·018에서 실제로 발생).
- 해결: 메인 문서·기록·요청이력·규칙·엑셀 사본을 git 저장소 `kokkiri-site\` 안으로 옮긴다. 효과: Codex·Claude 모두 승인 없이 읽고 쓰며, GitHub push로 함께 동기화되고, 다른 PC나 새 세션에서도 clone만으로 문서와 규칙을 얻는다.
- 추가: 줄바꿈을 `.gitattributes`로 LF 통일(두 에이전트가 번갈아 편집해도 diff 오염 방지). 배포는 로컬 인증이 필요 없는 GitHub push 방식만 유지(Codex는 이 PC의 wrangler 로그인 등을 쓸 수 없음).
- 작업 폴더 루트의 `CLAUDE.md`·`AGENTS.md`는 저장소 안 문서를 가리키는 짧은 안내로 바꾼다(Claude Code는 cwd와 상위 폴더의 CLAUDE.md를, Codex는 작업 폴더와 하위 AGENTS.md를 읽으므로 두 곳 모두 연결됨).

## 3. 수행 내용과 변경 파일 (Fable 직접 처리)

- 이동: `콕끼리 홈페이지 관리\메인.md`, `요청이력.md`, `코덱스_배포_지시문.md`, `기록\`(11개) → `kokkiri-site\`. 작업 폴더 루트 `CLAUDE.md`·`AGENTS.md`(전체 규칙) → `kokkiri-site\CLAUDE.md`·`AGENTS.md`.
- 복사: `콕끼리 홈페이지 관리\콕끼리 시드 관리표.xlsx` → `kokkiri-site\자료\콕끼리 시드 관리표.xlsx`(SHA-256 동일 확인). 관리 폴더의 엑셀 사본은 그대로 둠.
- 신규: 작업 폴더 루트 `CLAUDE.md`·`AGENTS.md`(안내용, 저장소 안 문서로 연결), `kokkiri-site\.gitattributes`(`* text=auto eol=lf`, png·xlsx binary), `콕끼리 홈페이지 관리\문서_위치_안내.md`.
- 규칙 문서 갱신: `CLAUDE.md` 1·2·4·5절(문서 위치, 문서도 commit·push, LF 통일, Codex 협업 전제), `AGENTS.md`(저장소 안 경로, 샌드박스 밖 폴더에 쓰지 않음, GitHub 로그인 창 시 사용자 승인), `메인.md`(문서 위치, 합의 규칙, 엑셀 사본 위치, 요청 027, 현재 상태).
- 커밋: 이 기록의 7절 참고.

## 4. 검증 결과 (Fable 직접 검토)

## 5. 최종 점검 (Fable)

- 사용자가 코덱스만으로 작업할 때 필요한 것: `kokkiri-site\AGENTS.md`·`메인.md`(규칙·상태), 번들 Node(테스트), GitHub push(배포). 모두 작업 폴더 안에서 승인 없이 가능하다. 유일한 사용자 개입은 GitHub 로그인 승인과 Cloudflare 대시보드 설정(비밀값)이다.

## 6. 미완료 사항과 다음 단계

- 요청 025의 사용자 계정 설정(GitHub 저장소·Cloudflare·D1·연결·비밀값)은 그대로 남아 있다. `kokkiri-site\README.md` 1~6단계.
- 저장소가 생기면 문서 포함 전체를 `git push -u origin main`.

## 7. Git 동기화·배포 결과
