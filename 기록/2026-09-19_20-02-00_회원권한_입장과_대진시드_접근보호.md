# 116 — 회원권한 입장과 대진·실시간·시드 접근 보호

## 요청과 시작 상태

- 공개 로그인 메뉴에서 운영진권한 위에 회원권한 항목 추가. 공지사항은 공개, 대진표·실시간대진·시드현황은 사용자 지정 공통 암호로 입장해야 이용 가능.
- 미입장 안내는 `회원만 볼 수 있는 메뉴입니다`. 운영진은 별도 회원 입장 없이 기존 권한으로 이용한다.
- 시작 HEAD 654e0db, 작업 트리 clean, git pull --ff-only origin main 최신 확인.
- 실제 회원 암호·운영진 비밀 주소·키는 소스/MD/명령 파일에 저장하지 않는다.

## 구현 내용과 운영 규칙

- `drizzle/0015_member_access.sql`의 `member_access_config`에 무작위 salt, PBKDF2-SHA256(100,000회) 결과를 EDITOR_KEY로 HMAC한 검증값, 설정 version만 저장. `member_login_limits`는 원본 IP 대신 HMAC 버킷과 만료 시각을 저장한다. 실제 암호는 저장하지 않는다.
- 운영진 인증 전용 `GET/POST /api/member-access/config`: GET은 configured/version만 응답, POST는 password와 현재 version을 받아 CAS로 변경한다. 최초 배포 후 HTTPS로 한 번 설정하며 실제 값을 파일에 남기지 않는다. 암호 변경 시 version이 증가해 기존 회원 쿠키가 모두 무효가 된다. EDITOR_KEY를 교체해도 검증값을 다시 설정해야 한다.
- 기존 EDITOR_KEY는 운영진 화면에도 쓰이는 공유 운영진 자격이므로 운영진은 회원 암호 설정 권한을 가진다. 개인별 계정 인증이 아닌 사용자가 요청한 공통 암호 입장 방식이다. 짧은 공통 암호의 전달/공유 자체를 방지하는 기능은 아니다.
- `POST /api/member-login`, `POST /api/member-logout`, `GET /api/member-session`. 회원 입장은 서버 검증·IP별 15분 5회 제한 후 7일 Secure/HttpOnly/SameSite=Lax `__Host-` 쿠키 발급. 실패 슬롯은 KDF 전에 원자적으로 예약하고 429에 Retry-After를 보낸다. 같은 Wi-Fi의 연속 오입력은 다른 회원 입장에도 잠시 영향을 줄 수 있다.
- 쿠키는 매 요청 서명·만료·DB 설정 version을 확인한다. 일반 로그아웃은 해당 브라우저 쿠키를 제거한다(이미 복사된 쿠키까지 서버에서 개별 폐기하는 개인 세션 시스템은 아님). 회원 역할은 조회 및 기존 회원용 실시간/승패 입력만 허용하며 운영진 수정 권한을 얻지 못한다.
- 회원 로그인/로그아웃/설정과 쿠키 기반 쓰기는 동일 Origin 및 application/json 필수. 설정/DB/비밀키가 없거나 손상되면 회원 접근은 거부된다. 암호를 잘못 입력했다는 401과 미입장 `MEMBERS_ONLY` 401은 구분한다.
- 공지 이외 데이터 API, 게시글 직접 링크, 홈 MVP 정보까지 서버에서 보호한다. 캐시에는 비공개 데이터를 저장하지 않는다.
- UI는 회원권한→암호 입력→입장, 미입장 접근 안내 및 로그아웃. 브라우저에 암호/운영진 키를 새로 복제하거나 localStorage 권한 플래그만으로 인증하지 않는다.
- Codex 본체는 서버·회귀·배포/문서, Terra는 회원 입장 UI, Astra는 인증 설계/최종 검토를 맡는다. 운영 경기/점수 시험 변경 없음.
