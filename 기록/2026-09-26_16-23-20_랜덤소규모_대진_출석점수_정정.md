- 사용자가 기존 오반영 출석점수 차감을 명시적으로 요청했다. 이전 정모의 유효 정산·승패와 최소 20점 보호를 보존한다.
- 시작 b753559, 작업 트리 clean, git pull --ff-only origin main 최신 확인.
- 운영 대진 읽기 조회: 9/23 스포원 14명, 9/18 양산 12명, 9/16 스포원 16명이 전체 랜덤 일반마감 상태. 9/20·9/25 미반영마감은 제외. 현재 최신 정모는 9/26 30명.
- 실제 차감 전에 DB 정산 이력 기반 계획과 변경 전 백업, 동시 수정 방지, 재실행 중복 차감 방지를 검증한다. 시험 정산은 가상 DB에서만 한다.

## 수행·검증·배포

- 핵심 DB 정정은 Codex 본체, 향후 규칙 및 기존 회귀 검증은 GPT-6 Sol 분담, 최종 GPT-6 Astra 검토.
- `attendance-policy.js`: 전체 랜덤 또는 고유 참가명단 15명 이하이면 출석 0. 기존 마감 API에 공통 함수 적용. 15/16명, 혼합/랜덤, 회원/게스트, 불참/늦참/휴식, 승패·MVP·20점 보호·취소·미반영 회귀 검증 PASS.
- `attendance-correction.js`: 운영진만 조회 가능한 순수 정정 계획(GET), fingerprint 확인 후 POST로 반영. 최신 roster revision을 확보해 변경 전 백업과 정산 이벤트·현재 점수·과거/현재 순위를 같은 트랜잭션으로 저장한다. 대상 정산 이벤트를 0 출석으로 수정해 재차감 방지. 원 관측 원장은 그대로 보존한다.
- 사람별 정산을 다시 계산해 이후 20점 보호가 초과점수를 흡수한 경우 과잉 차감하지 않고, 수동 절대 점수·회원 이관을 보존한다. 수정 이력은 사람 변경 사유로 남기되 명시적 수동 초기화와 구분하여 주간 표시를 유지한다. 게시글 내용·승패 입력·마감 시각·MVP는 바꾸지 않는다.
- Astra 검토에서 수동 점수 변경 사이의 동점 순서, 수동 수정 이전의 과거 20점 보호 순위 결함 2건을 찾아 수정했다. 수동 변경도 순위 계산에 시간순으로 반영하고, 과거 보호는 그 시점까지의 이력에서 읽는다. 독립 비교 DB(처음부터 오반영 없이 정산)와 현재 점수·순위·정산 이벤트·과거 순위가 일치하는 회귀 검사 PASS.
- 출석 정정 전용 검사: 읽기 전용 미리보기, 백업/실패 시 전체 롤백, 동시 변경 409, 중복 차감 방지, 권한/Origin, 기존 소규모 승패 보존, 이관자 1회 차감, 마감 취소 델타 일치 PASS. 필수 번들 Node check-login.mjs 전체 및 git diff --check PASS.
- 공개 기존 API 조회로 대상자 중 최소 38건의 +1 정산을 확인했다. 해당 인원에 최초 대상 마감 이후 수동 점수 수정은 없었다. 운영 명단 회원 68명·전체 107명, 마감 대진 9건의 원본 응답을 메모리에 읽어 변경 전후 비교를 준비했다. 실제 반영 수는 DB 정정 계획에서 최종 확인한다.
