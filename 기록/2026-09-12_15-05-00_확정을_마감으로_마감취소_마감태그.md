# '확정'을 '마감'으로, 마감 취소 기능, 대진표 목록 마감 태그

- 작업 시각: 2026-09-12 15:00 ~ 15:15 KST
- 작업 도구: Codex 세션(로컬 구현, 커밋 전) + Claude Code(Opus 4.8, 검증·테스트·배포)
- 관련 요청: 053, 054

## 1. 요청 번호와 요청 요약

- 요청 053: 확인창 등의 '확정' 문구를 '마감'으로. (Codex가 함께 '마감 취소' 기능도 구현.)
- 요청 054: 대진표 목록에서 마감된 대진은 제목 오른쪽에 작은 회색 '마감' 표시.

## 2. 상황 (협업)

- Codex 세션이 boards-client.js·boards-style.js·boards.js를 로컬에서 수정(커밋 전)해 두었다. 다른 세션이 같은 워킹트리를 공유하는 협업 구조(Codex+Claude). 본 세션(Opus)이 그 변경을 검증하고 커밋·배포하는 역할을 맡았다(중복 구현 없음).

## 3. 변경 내용 (Codex 구현, 본 세션 검증)

- 문구(053): endMatch 버튼 "대진 종료"→"대진 마감". 확인창 "정말 확정하시겠습니까?…" → "정말 이 대진을 마감할까요? 마감하면 출석·승패 점수가 시드현황에 반영됩니다. (마감 후에도 되돌릴 수 있어요.)". end-note·편집 안내의 '대진 종료(점수 확정)'도 '대진 마감'.
- 마감 취소(053): 정산된 대진 상세에 운영진 전용 `#unsettlePost`('마감 취소') 버튼(확인창 딸림). 서버 `POST /api/posts/:id/unsettle`(운영진 키). `unsettleSchedule`: 가장 최근 마감본만 허용, `ranking_events` 델타를 역산해 points·attendance·wins·losses 원복, `orderRankingRows`로 순위·시드 재계산, payload의 settledAt→null·mvp→[]·title→preTitle 복원, ranking_events·ranking_settlements의 해당 기록 삭제. settleSchedule은 원제목 복원을 위해 `preTitle:post.title`을 payload에 저장.
- 목록 태그(054): `/api/posts` 목록 쿼리에 `json_extract(payload,'$.settledAt') AS settledAt` 추가. 클라이언트 board 목록이 `kind==='schedule'&&p.settledAt`이면 제목 뒤에 `<span class="settled-tag">마감</span>`. `.settled-tag` CSS(작은 회색 #8a97a0 pill).

## 4. 검증 결과 (Opus 본체)

- `node check-login.mjs` PASS. 마감 취소 회귀 테스트 추가: 새 대진 생성→기록→마감(시오 +2, 출석1·승1)→비운영진 unsettle 403→운영진 unsettle 200→점수·출석·승 원복(uPre, 0, 0)→settledAt null.
- 로컬 브라우저 e2e(운영진, legacy 대진표):
  - 버튼 "대진 마감", 확인창 "정말 이 대진을 마감할까요?…되돌릴 수 있어요", 예/아니오 확인.
  - 마감(정산) 후 로토 104→107(+3, 출석1·승3·패1), 백구 88→89(+1). 목록 API가 settledAt 반환, 목록 화면 제목 뒤 회색 '마감' 태그 표시(색 rgb(138,151,160)).
  - 상세에 '마감 취소' 버튼. 마감 취소 실행 → 점수·출석·승·패가 정산 전(로토 104/0/0/0, 백구 88/0/0/0)으로 정확히 복원, settledAt 해제, 제목 원복.

## 5. 최종 점검 (Opus 본체)

- 마감 취소는 '가장 최근 마감본'만 되돌릴 수 있어 이전 정산 위에 쌓인 상태를 훼손하지 않는다. 운영진 전용·확인창. 콕끼리는 아직 실제 정산 이력이 없어 라이브 영향 없음.
- 확인창이 "마감 후에도 되돌릴 수 있어요"라고 안내하는 것과 마감 취소 기능이 일치한다.
