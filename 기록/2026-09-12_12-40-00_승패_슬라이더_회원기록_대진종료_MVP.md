## 1. 요청 번호와 요청 요약

- 037: 승패 버튼을 회원(=링크를 가진 누구나, 로그인 없음)도 누를 수 있게. 승패 UI를 양쪽 '승리' 라벨 사이에서 초록 원형 노브가 누른 쪽으로 미끄러져 겹치는 토글로.
- 038: 모든 채점 경기가 끝나면 운영진에게만 '대진 종료' 버튼 → 예/아니오 확인 → 출석 +1(모임당 1회)·승 +1·패 -1 자동 시드 반영 + MVP(랜덤 제외·채점 경기 전승 회원, 게스트 제외)를 뽑아 제목을 'N월 N일 정모의 MVP A B C'로, 반짝이는 효과.
- 039: 랜덤 게임은 점수에 반영되지 않으므로 랜덤 체크된 경기에는 승 버튼 자체가 없게.
- 040: 반짝이는 MVP 표현을 홈의 3개 메뉴 카드와 '함께한지' 푸터 사이에 작게(너무 눈에 띄지 않게) 표시, 표시 기한 약 5일.

## 2. 계획 (Fable/본체)

- 핵심 설계 결정(사용자에게 안내): 이 사이트는 회원 로그인이 없어 "회원=링크를 가진 누구나". 안전장치로 결과 기록은 정산 전 대진표에만 허용, 정산(점수 확정)은 운영진 전용, 정산 후 잠금.
- 데이터 모델: 라운드별 매칭 방식(method)을 대진표 payload에 저장하도록 서버 validate 확장(039의 랜덤 판별·정산 제외를 위해 필요). 채점 라운드 = method!=='random'.
- 서버: (a) 공개 단일 결과 엔드포인트 `POST /api/posts/:id/result`(운영진 키 불필요, results만 병합, version 낙관적 동시성으로 동시 기록 충돌 방지, 랜덤·정산완료 거부). (b) 정산에서 랜덤 라운드 제외(완료 판정·승패 점수), 출석은 전원 1회. (c) MVP 계산·제목 갱신·payload.mvp 저장. (d) 040용 `GET /api/mvp`(가장 최근 정산 대진표의 mvp·정산시각).
- 클라이언트: 승패 슬라이더(winToggle: 양쪽 '승리'+가운데 노브), 상세에서 누구나 기록(recordResult→/result, 충돌 재시도), 대진 종료 버튼(모든 채점 완료 시 운영진만)+예/아니오 confirmDialog, MVP 제목 반짝임, 홈 MVP 배너(5일). 랜덤 라운드는 토글 대신 안내.
- 분업: Sonnet A=서버(boards.js), Sonnet B=클라이언트+스타일. API 계약 고정 후 병렬. 통합 테스트·e2e는 본체.

## 6. 미완료 사항과 다음 단계

- MVP 제목은 대진표 이름을 대체함(원 제목은 정산 시점에 MVP 문구로 바뀜). 원 제목 보존이 필요하면 별도 요청.
- 라운드 방식(method)은 이번 배포 이후 생성/저장된 대진표부터 저장됨. 기존(배포 전) 대진표는 method가 없어 전부 채점으로 처리(옛 동작 유지).
