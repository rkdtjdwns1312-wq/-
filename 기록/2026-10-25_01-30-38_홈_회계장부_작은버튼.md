# 요청 131 — 회계장부와 쪽지 메모

## 요청과 계획

- 기존 홈 메뉴 4개 아래 가운데에 회계장부 버튼, 모바일에서는 다섯 번째로 표시. 기존 카드보다 약 ¼ 크기, 터치 영역/문자 가독성 유지.
- 사용자 답변: 홈페이지 내부 장부를 만들며 일반 회원은 조회만, 운영진은 편집. 날짜/항목/수입/지출/누계와 긴 메모를 지원한다.
- 추가 요청: 내용이 있으면 메모보기 버튼으로 쪽지처럼 열기. 기존 글꼴과 네이버 느낌의 초록/흰색 디자인으로 통일.
- pull 최신 c9a07ef, 깨끗한 작업 트리 확인.

## 구현

- 홈 4개 카드 아래 회계장부 버튼 추가. 모바일 150×48px, 데스크톱 최대240×64px. 회원 로그인 필요.
- DB singleton ledger_state와 ledger_revisions 변경 전후 감사 스냅샷. GET /api/ledger는 회원·운영진, PUT은 운영진만. JSON/Origin/버전/중복 operation을 서버 검증한다.
- 시작 잔액, 날짜별 수입·지출, 자동 누계. 같은 날짜는 입력 순서. 원 단위 정수, 행별 수입·지출 한 가지, 최대500행/전체512KiB. 메모 최대5,000자, 줄바꿈 유지·HTML 이스케이프.
- 메모 입력→적용→장부 저장 순서. 회원은 메모보기로 읽기만 가능. 빈 메모에는 조회 버튼을 만들지 않는다.
- 동시 편집 충돌은 자동 덮어쓰지 않고 초안을 유지. 통신 실패 재시도는 같은 operation으로 중복 저장 방지.
- 기존 홈으로 가기/글꼴/초록색 버튼과 통일. 모바일 표는 내부 좌우 스크롤, 요약은2열.
- 기존 대진·실시간대진·시드·점수 변경 없음. 실제 장부 데이터는 임의로 만들지 않는다.

## 모델과 검증

- 경량 작업: GPT-6 Luna(이 환경에서 이전 Luna 대신 사용), 홈 버튼 CSS와 실제 UI 팩터리 테스트·디자인. GPT-6 Astra: DB·권한·백업·최종 검토. 본체는 UI/연결/문서/실화면 통합 검증.
- 최초 Astra 검토 및 브라우저 테스트에서 PUT Content-Type 누락(415)을 발견해 수정. 테스트에 JSON 헤더 회귀 검사 추가.
- 누적 감사 이력의 단일 백업 크기 초과 위험을 발견해 UTF-8 512KiB 분할 백업으로 보완. 이전 백업 호환, SHA-256/크기/누락 검증, 원자적 저장·만료 정리 집중 검사 PASS. Astra 최종 검토 추가 차단사항 없음.
- check-login.mjs 전체 PASS(새 장부 서버/클라이언트 검사 포함). 실화면에서 비회원 차단, 운영진 입력·메모·저장, 회원 편집 버튼 없음 확인.
- 로컬 가상 장부: 시작100,000+수입30,000−지출10,000=누계120,000 확인. 운영 DB에는 시험값을 쓰지 않음.
- 모바일390px 홈 버튼150×48, 320px 장부/메모 문서 가로넘침 없음. 기존 Do Hyeon/Noto Sans KR 상속 확인. 좁은 운영진 화면은 요약을1열로 배치해 숫자 가독성 보완.
- 최종 초록/흰색 장부·쪽지 실화면: `2026-10-25_회계장부_메모_로컬.png`(가상 테스트 금액). 공개 배포는 후속 확인 예정.

## 핵심 명령

홈에 작은 회계장부를 추가하고 회원 조회·운영진 편집, 날짜별 자동 누계와 메모보기 쪽지를 기존 디자인으로 구현한다.
